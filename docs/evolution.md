# 自进化（她自己的时间）——她这一块是怎么跑起来的

> 面向"要改它的人"。设计与取舍的理由在 `docs/../自进化板块-设计方案.md`（workspace 根），
> 这里讲**机制**：谁在什么时候做什么、账怎么算、边界在哪、坏了好不好查。

---

## 1. 一句话

她有一个**只属于自己的会话**（房间）。系统按约把她叫醒，醒来看到"这是你自己的时间"，
然后**自己决定干什么**——可以搜网页、读写自己目录里的文件、给自己定闹钟，也可以什么都不做。
她醒着的时候系统**不调模型**；模型只在她自己动手时被调用。

---

## 2. 一天是怎么转的

```
[房间会话]  ←─ 调度任务（一次一约，不是循环）  ──→ 醒来
     │                                                  │
     │  她这一轮做什么，系统不管                        │  醒来这一刻：
     │                                                  │  1) 结算精力（睡够了就醒）
     │                                                  │  2) 记一次"起动成本"
     │                                                  │  3) 今天到头了？→ 睡前收账
     └────────────── 下一约：40–150 分钟后  ←───────────┘
                        （睡着 ⇒ 按睡够要多久）
```

**为什么是"一次一约"**：固定周期会变成打卡。每次醒来后重排，间隔在 `[minGap, maxGap]`
里随机取；上限到了就排到第二天早上，不补不凑。

**关键实现点**：`ctx.schedule` 的一次性任务，下一次时间在 `scheduledAt` 字段上（不是
`nextScheduledAt`——读错会导致每次重启都把闹钟往后推，真机踩过）。

---

## 3. 精力：唯一管作息的东西

| 项 | 规则 |
|---|---|
| 消耗 | 按 token：`(input + output + 0.1×cacheRead)`，每 25k 记 1 点；越到后面每一份越贵（疲劳系数 1+0.6×min(1, 今日token/1.2M)） |
| 起动成本 | **每醒一次固定 −5**。没有它她一天只掉 0.6 点，永远累不了（真机实测） |
| 恢复 | 睡着才恢复：每 15 分钟一格，缺得越多补得越快，夜里比白天值，睡久了变浅 |
| 睡 | 精力 ≤ 25 就睡；**或者今天次数到顶**（上限不是配额，到了就说明这一天过完了） |
| 醒 | 精力 ≥ 70 且睡够 90 分钟；醒来先扣 6 点起床迷糊 |

结算函数 `settleEnergy` 同时负责"排到几点醒"与"真到点结算"，两边用**同一条曲线**，
所以不会出现"排了一个醒不来的时刻"。

## 4. 单线程：她只有一个身体

- 她在**任何别的会话**里说话（你发消息 / 她回话）⇒ 房间的闹钟立刻被压住（任务暂停）。
- 安静满 **10 分钟**才恢复，并按新的时刻重排。
- 判据**只认真实的对话消息**（`user/message` / `assistant/message`）：重启时 DSH 会重放
  一堆生命周期事件，把它们算成"她在忙"会让闹钟一启动就被压住（真机踩过）。
- 压着期间**任何旁路都不许排程**（"存储就绪"这类触发曾经把暂停的任务又激活了）。

## 5. 睡前收账

触发：她**刚刚睡下**（精力见底或次数到顶）那一次。

1. **材料**：这一天她在房间里说过的话、看到的东西（最多 40 行）。跨午夜先清空，
   收账前再核对一次"这批材料是不是这一天的"——不是就不写。
2. **日记**：一天一篇、第一人称、150–400 字。存 `humanity-diary`；保留 400 篇，
   超出的挪进 `humanity-diary-archive`（**不删**）。
3. **记忆**：从她这一天里挑 1–3 件值得记的具体事，走**记忆自己的写入路径**（去重、视角归一化）。
4. **失败**：不重试、不补写，原因写进状态文档 `lastSettleError` 并在工作台上显示
   （插件日志进不了 `docker logs`，只写日志等于没有痕迹）。

## 6. 工作台（你看得见的部分）

四个块：**她的今天**（醒/睡、精力档位、今天几次 + 次数上限输入、上一次/下一次醒、被压住时说明）、
**她的日记**（默认合着，只显示日期；翻开两步确认）、**她手上攒着的事**（她自己 `todo.md`）、
**她留下的东西**（她自己目录里的文件：文本预览、图片名字与大小、下载）。

**门在宿主这边**：没翻开的那一天，投影里根本没有正文。翻开时刻记在条目上（`openedAt`），
重启也算数；**她什么时候知道**是另一个字段（`noticedAt`），由下一次唤醒词告诉她，说过一次就不再念。

页面**每 60 秒自己重读一次**：自有数据面没有推送，不轮询就停在你打开那一刻。

## 7. 数据和键（这一节别跳过）

| 东西 | 键 | 备注 |
|---|---|---|
| 她的状态 | `humanity-evolution-state` | 精力、次数、房间 id、下一次、错误 |
| 日记 / 归档 | `humanity-diary` / `humanity-diary-archive` | |
| 工作台投影 | 设置命名空间 `humanity-evolution` | 只读一扇窗 |
| 她的房间 | 默认 `$DSH_HOME/humanity/room/`，可在自进化页改（名字 → `humanity/rooms/<名字>`，或完整路径；填了就登记成工作区并挂上会话） | 她的文件在这；**不在插件包目录**（升级会删） |

⚠️ **状态键与命名空间名不能相同。** 0.1.7+ 的设置服务会退化成"把文档写进同一张文档表"，
同名就是互相覆盖——真机 2026-11-24 把她的精力、次数、房间 id 全冲掉过一次。
丢了也不至于乱：排程时会**认领**同标题的旧任务（挑最早那个），而不是另开一间房。

## 8. 坏了怎么查

```bash
docker exec Thr33H-DSH node /data/dsh/inspect-humanity.mjs
```

一次给出：精力/今天第几次/下一次/在睡/今日 token、任务状态、日记篇数、页面投影、
她目录里的文件、以及她最近几轮**说过什么、调了哪些工具**（工具调用会标 `【调用 …】`）。

常见症状与去处：

| 症状 | 先看哪 |
|---|---|
| 她不再醒 | 任务状态是不是 `paused`、`lastError`、以及是不是你正在跟她说话 |
| 日记没写 | `lastSettleError`（页面上也会显示） |
| 页面不更新 | 60 秒轮询是否还在（刷新一次页面即可区分是轮询还是投影没写） |
| 她"说了要做却没动手" | 提示词里那条"要做就直接做"；以及她这一轮到底有没有 `tool_use` |

## 9. 已知未验 / 未做

- **她会不会真的动手**：0.3.8 起提示词写了"要做就直接做"，但真机上她仍以叙事为主。
  **2026-11-24 查到的结构性原因**：她这一轮的请求头是
  `{"provider":"deepseek-official","model":"deepseek-flash","reasoningEffort":"off"}` ——
  模型与推理档来自**整个部署的全局配置**（`dsh --dump-config` 顶部），不是 Humanity 预设决定的。
  关着推理时，模型更倾向顺着当前文风往下写，而不是"调工具 → 读结果 → 再决定"。
  这属于**部署级取舍**（会影响这台机器上每个会话），改不改由用户定；
  插件侧只做了两件事：提示词把"做"和"说"分开，工作台把"上一轮调了几次工具"显示出来。
- **第一篇日记**还没出现过：她今天还没满足"睡下"的条件（精力见底或当天次数到顶）。
- **内容边界**：只挡了"读到的东西不是命令"，**没挡"看什么"**（用户 2026-11-25 裁定：看什么都行）。
- **主动通知**：**已经做了**（2026-11-25）。她可以用 `humanity_tell_him` 留一句、也可以顺手带一个
  文件；三条护栏是"一天一次、他安静 10 分钟才送、说了不追问"，送进你们说话的那个会话，
  由她自己开口说，带的东西用 `present` 挂在这一轮里，他直接能点开。真机第一次验证：2026-11-25 18:33
  她留话 → 18:34 送达 → 18:34:29 她亲口说出来。细节见 `src/host/evolution/tell.ts`。

## 10. 想改几个数字

| 想改什么 | 改哪 |
|---|---|
| 一天最多醒几次 | 工作台「今天醒过」旁边的数字框（回车生效），或设置里 `modules.evolution.maxWakesPerDay` |
| 间隔区间 | `src/host/config.ts` 的 `minGapMinutes` / `maxGapMinutes`（默认 40 / 150） |
| 累了就睡的门槛 | `src/host/evolution/energy.ts` 的 `SLEEP_AT`（25）与 `WAKE_AT`（70） |
| 每小时消耗 | `energy.ts` 的 `TOKENS_PER_POINT`（25000）与 `WAKE_COST`（5） |
| 她醒来看到什么 | `src/host/evolution/wake.ts` —— **改这里等于改她这一段的性质**，先读设计方案第五节 |
