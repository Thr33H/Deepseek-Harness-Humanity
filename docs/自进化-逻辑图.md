## 一、三条通道（卡片）

全部建成**永远不会自己触发**的卡片：`timing` 给 RRULE 锚在 2099-12-31。DSH 建任务必须给时间，给一个到不了的时刻，它就只是一根管道。

| 通道 | 投到哪个会话 | 插件什么时候触发它 |
|---|---|---|
| **叫醒** | 她的房间 | 到了"最早可以叫"的时刻，且她的房间**空闲** |
| **收账** | 她的房间 | 收账条件成立，且房间空闲，且今天还没提醒过 |
| **留话** | 你的会话 | 她有话待送，且**你的会话空闲**，且今天还没送过 |

插件触发的方式：**改卡片内容 → `run`（立即执行）→ 核对送达**。

`run` 的性质（查源码确认）：投一次，**不消耗也不移动**原来排的时间——所以同一张卡片可以反复用。

## 二、唯一的心跳：插件每 60 秒看一次

```text
每 60 秒：
  ① 该叫醒她吗？
     到"最早可以叫"的时刻了？       （插件自己算的，不是闹钟）
     她的房间安静够久了？（比如 ≥ 90 秒没有新消息/工具调用）
     → 都满足：走【叫醒通道】

  ② 该收账吗？
     精力 ≤ 25 或 今天次数到顶？
     且 今天还没提醒过（collectAt 为空）
     → 先做三件事：材料写成文件 → 通道内容改成"写日记" → 等房间空闲再 run

  ③ 她有话要送吗？
     待送队列非空？且 今天没送过？且 你的会话安静够久？
     → 走【留话通道】

  ④ 投出去的那几条，核对送达了吗？
     目标会话里出现这条消息了吗？
     → 没出现：下一轮再投，最多补一次，然后记原因
```

**为什么必须有这层**：2026-11-26 实测，闹钟自己响的时候正好撞进她正在跑的那一轮，消息被排到"下一轮"，而下一轮没发生——她永远没看到。投的动作交给插件，就不会撞。

## 三、一天从头到尾

```text
【算时间】插件纯计算
  精力 + 今天第几次 + 上次几点醒 → nextAt（最早可以叫醒的时刻，40–150 分钟后）
  （这只是"最早时刻"，不会自己响）

【叫醒】心跳判断：到 nextAt 了 + 房间空闲 → 改通道内容 → run → 核对
  她读到的醒来词：
   现在只有你自己 / 这里没有别人，<称呼>不在 / 时间
   你能做什么（从她真实工具表生成）
   要就直接做 / 手上的事 / 你写的东西他看得到 / 门禁 / 何时停

【她的这一轮】做什么由她定（查资料、读写文件、定闹钟、留话、什么都不做）
  插件在旁边：记材料 · 数工具调用 · 扣精力 · 注入工具清单 · 留"上次说到哪"

【判定】这一轮结束 + 精力/次数
  ├─ 没到 → 回到【算时间】
  └─ 到了 → 【收账】

【收账】交还给她自己
  ① 插件把两栏材料写成文件：日记材料-<日期>.md
  ② 通道内容改成：[收账] 只做两件事 read 材料 → write 日记 → 停
  ③ 等房间空闲 → run → 核对
  ④ 她写出 diary-<日期>.md
  ⑤ 插件看到文件里真有字 → 收进日记本 → 清材料 → 这一天结束
  ⑥ 她没写 → 不催（一天只提醒一次）→ 这一天没有日记，明天照常

【跨天】
  日期变了 → 关旧房间 → 新开一间 → 当场把会话名改成日期 → 换通道的目标会话
```

## 四、状态文档要记什么

| 字段 | 作用 |
|---|---|
| `wakeTaskId` / `collectTaskId` / `tellTaskId` | 三条通道的卡片 id |
| `nextAt` | **最早可以叫醒的时刻**（语义变了：不再是闹钟） |
| `dayKey` / `dayCount` / `lastWakeAt` | 今天第几次、上次何时醒 |
| `energy` / `energyAt` / `sleepingSince` | 精力与睡下时刻 |
| `settling` / `collectAt` | 正在等她自己写日记的那一天；今天提醒过没有 |
| `capabilities` | 她上次真实可用的工具名 |
| `talkSessionId` | 她最近在哪个会话跟你说话（留话要投到那儿） |
| `roomSessionId` / `roomDay` / `roomTitleNote` | 她的房间属于哪一天、名字对上没有 |
| `roomDir` / `roomWorkspace` | 这间房间落在哪个目录、挂在哪个工作区（配置改了就拿它比对，决定要不要搬家） |
| `lastError` / `lastSettleError` | 失败原因（插件日志进不了 docker logs） |
| **新增：每个会话的最后活动时刻** | 空闲判断用（或只在内存里算，重启后重新累积） |

## 五、谁用模型

**用**：她自己那段时间、写日记、情绪评估（你每句）、记忆整合、她自己整理信息层。

**不用**：算最早叫醒时刻、建/改/触发卡片、拼材料、判断文件写没写、空闲判断、跨天换房间、核对送达。

## 六、边界与兜底

| 情况 | 处理 |
|---|---|
| 精力见底 / 次数到顶 | 判该睡 → 收账，不再算下一次 |
| 次数上限 0 | 不算下一次（只能手动叫） |
| 你一直在说话（单线程） | 她的通道被压住；你安静 10 分钟才恢复 |
| 她没写日记 | 不催（一天一次）、不补、不代笔 |
| 通道投递失败 / 卡片被删 | 记原因；下一轮用 id 找不到就重建一张 |
| 投出去但没出现在会话里 | 补投一次；仍失败 → 记原因，等下一轮 |
| 收账进行中又满足条件 | `settling` 挡住，不会有第二次 |
| 跨午夜 | 先给昨天的本子拍快照再换本 |
| 她写日记期间 | 不触发叫醒通道，不打断 |
| 重启 | 全部落盘：状态、材料、日记、三条通道的 id |
